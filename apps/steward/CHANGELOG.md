### Fix Product Tour "Show Demo" Auto-Advance Bug
- **Problem**: When clicking the "Show Demo" button on the Tour Remote Control (e.g., for the Metrics Filter Mode on slide 9), the tour would unexpectedly advance to the next slide immediately instead of playing the demo. This occurred because `useTourSimulation` triggers native `.click()` events on DOM elements (like the filter buttons) inside the Joyride `target` area. Even after `react-joyride` was commanded to pause (`run={false}`), it maintained its native click listeners on the target element and interpreted the simulated button click as a user click on the target, prompting it to emit a `step:after` (action: 'next') event, which immediately skipped the demo and advanced the slide.
- **Solution**: Updated `handleJoyrideCallback` in `useAppTour.ts` and `ProductTour.tsx` to immediately discard all Joyride callbacks if `activeDemo !== null`. Added explicit `type="button"`, `e.preventDefault()`, and `e.stopPropagation()` to the buttons inside `TourRemoteControl.tsx` to prevent any native form or bubbling side-effects.
### Fix Product Tour Empty Data
- **Problem**: When taking the product tour, the demo media data wasn't being injected into the local database upon advancing from the introduction slide, leaving the dashboard and metrics entirely empty during the tour.
- **Solution**: Refactored `App.tsx` hook initialization order to allow `handlePopulateDemo` from `useDemoActions` to be passed into `useAppTour` as the `injectDemoData` callback. Updated `goToTourStep` inside `useAppTour` to invoke `injectDemoData` when transitioning to `step > 0` if demo data hasn't already been inserted.
### Fix Product Tour Auto-Launch
- **Problem**: When launching the application after a full reset, clicking the "Tour" button for the first time would successfully populate the demo data but failed to actually start the tour (requiring a second click).
- **Solution**: Removed the early return inside the `if (scannedFilesList.length < 5)` block in `Sidebar.tsx` and ensured `setTourStepIndex(startStep)` and `setShowTour(true)` are called immediately after initiating the demo data injection, so the tour overlay appears instantly on the first click.
### Fix Product Tour Auto-Launch Demo Data Injection and Cleanup
- **Problem**: The product tour would launch successfully on first click but would fail to populate the dashboard with the demo data, leaving the view completely empty. Additionally, skipping or permanently hiding the tour did not properly remove the demo data.
- **Solution**: Re-wired `onPopulateDemo` in `Sidebar.tsx` to properly await the top-level `handlePopulateDemo` (which calls `setHasCompletedScan(true)` so the UI correctly switches from empty state to rendering metrics). Updated `useAppTour.ts` to execute `clearDemoData` (passing `flushDemoDataOnly` from `useDemoActions`) when the user cancels or reminds later, ensuring the mock data is cleaned out and the application is left in its default empty state.
### Fix Product Tour Auto-Launch and Immediate Data Injection
- **Problem**: The product tour did not appear automatically after a full application reset. Additionally, the demo data was only injected when advancing past the initial welcome screen, resulting in an empty dashboard view behind the welcome dialog.
- **Solution**: Refactored the `showTour` initialization in `useAppTour.ts` to immediately update `localStorage` and return `true` on the very first load. Furthermore, a `useEffect` hook was added to trigger the demo data injection (`handlePopulateDemo`) immediately when the tour starts, guaranteeing the sample items are visible under the overlay.
